Quando é publicada uma versão mais recente, o ipmideck mostra uma notificação uma única vez, e junto à versão na barra lateral fica um botão de atualização até a instalar: uma seta para cima, ou um escudo numa versão de segurança. Ambos abrem as notas da nova versão e, quando o ipmideck a consegue instalar sozinho, o botão **Transferir e instalar**.

## O que o botão faz

Antes de alterar o que quer que seja, o ipmideck faz uma cópia de segurança da base de dados, da chave de encriptação e do `config.yaml` em `backups/` no [diretório de dados](/pt/configuration#onde-a-configuração-fica).

| Instalado com | Resultado |
| --- | --- |
| pip num ambiente virtual, pipx, uv | Instala a nova versão e reinicia o ipmideck. A página recarrega sozinha quando a nova versão estiver em execução. |
| pip, pipx ou uv no Windows | O ipmideck para para que a atualização seja instalada; depois, volte a iniciá-lo. O progresso é registado em `update.log` no diretório de dados. |
| Docker com Watchtower | O Watchtower descarrega a nova imagem e substitui o contentor. A página recarrega sozinha. |
| Docker sem Watchtower | A janela mostra o comando a executar no anfitrião Docker. |
| Checkout git, Python do sistema, instalação editável | A janela explica o motivo e mostra o comando a executar; um Python gerido pelo sistema atualiza-se da mesma forma que foi instalado. |

## Requisitos

- O início de sessão tem de estar ativo: o botão substitui o programa em execução.
- O botão não está disponível no modo de demonstração.
- Para reiniciar sozinho, o ipmideck tem de ter sido iniciado com o comando `ipmideck`. Se foi iniciado de outra forma, instala a atualização e pede-lhe que o reinicie; no Windows mostra o comando em vez disso.

## Docker com Watchtower

Um contentor não consegue substituir a sua própria imagem, e dar ao ipmideck acesso ao socket do Docker dar-lhe-ia o controlo do anfitrião. Um contentor [Watchtower](https://github.com/nicholas-fedor/watchtower) separado faz a substituição quando o ipmideck o pede.

<Steps>
  <Step title="Etiquete o contentor do ipmideck">
    Inicie o ipmideck com a etiqueta que permite ao Watchtower geri-lo:

```bash
docker run -d --name ipmideck --network host \
  --label com.centurylinklabs.watchtower.enable=true \
  -v ipmideck-data:/data devluigi06/ipmideck:latest
```
  </Step>
  <Step title="Inicie o Watchtower">
    Inicie o Watchtower com a API HTTP ativa, acessível apenas a partir do anfitrião:

```bash
docker run -d --name watchtower \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -p 127.0.0.1:8080:8080 \
  -e WATCHTOWER_HTTP_API_UPDATE=true \
  -e WATCHTOWER_HTTP_API_TOKEN=replace-with-a-long-random-token \
  -e WATCHTOWER_LABEL_ENABLE=true \
  nickfedor/watchtower
```
  </Step>
  <Step title="Ligue o ipmideck">
    Adicione o endereço do Watchtower e o token na secção `updates:` que o `config.yaml` já tem e reinicie o ipmideck:

```yaml config.yaml
updates:
  watchtower_url: http://127.0.0.1:8080
  watchtower_token: replace-with-a-long-random-token
```

    As mesmas definições existem como `IPMIDECK_UPDATES_WATCHTOWER_URL` e `IPMIDECK_UPDATES_WATCHTOWER_TOKEN`. Com Docker Compose, em que ambos os contentores partilham uma rede, use `http://watchtower:8080` como endereço.
  </Step>
</Steps>

<Warning>
  O Watchtower controla o Docker através do seu socket. Use um token longo e aleatório e mantenha a porta associada a `127.0.0.1`, como no exemplo.
</Warning>

<Note>
  O Watchtower descarrega a etiqueta que o contentor já usa. Com `latest` passa para a versão mais recente; um contentor fixado numa etiqueta de versão (por exemplo `2.0.0`) mantém-se nela.
</Note>

## Se a instalação falhar

A janela mostra o motivo e a saída do instalador, juntamente com o comando para instalar a atualização manualmente. Nada é removido: a cópia de segurança feita antes da instalação está em `backups/`, e [Cópia de segurança e restauro](/pt/backup-restore) explica como a repor.
