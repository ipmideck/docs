title: "Web UI からの更新"

---

新しいバージョンが公開されると、ipmideck は通知を 1 回だけ表示し、インストールするまでサイドバーのバージョンの横に更新ボタン (上向きの矢印、セキュリティリリースの場合は盾) が表示されます。どちらも新しいバージョンのリリースノートを開き、ipmideck が自分でインストールできる場合は **ダウンロードしてインストール** ボタンも表示されます。

## ボタンの動作

変更を加える前に、ipmideck はデータベース、暗号化キー、`config.yaml` を [データディレクトリ](/ja/configuration#設定の場所) の `backups/` にバックアップします。

| インストール方法 | 結果 |
| --- | --- |
| 仮想環境の pip、pipx、uv | 新しいバージョンをインストールして ipmideck を再起動します。新しいバージョンが動作するとページは自動で再読み込みされます。 |
| Windows の pip、pipx、uv | 更新をインストールするため ipmideck が停止します。完了後にもう一度起動してください。進行状況はデータディレクトリの `update.log` に記録されます。 |
| Docker (Watchtower あり) | Watchtower が新しいイメージを取得してコンテナを置き換えます。ページは自動で再読み込みされます。 |
| Docker (Watchtower なし) | Docker ホストで実行するコマンドがダイアログに表示されます。 |
| git チェックアウト、システムの Python、編集可能インストール | ダイアログに理由と実行するコマンドが表示されます。システム管理の Python は、インストールしたときと同じ方法で更新します。 |

## 要件

- ログインが有効である必要があります。このボタンは実行中のプログラムを置き換えるためです。
- デモモードではボタンを使用できません。
- 自動で再起動するには、ipmideck が `ipmideck` コマンドで起動されている必要があります。それ以外の方法で起動した場合は、更新をインストールしたうえで再起動を求めます。Windows では代わりにコマンドを表示します。

## Docker と Watchtower

コンテナは自身のイメージを置き換えられません。また、ipmideck に Docker ソケットへのアクセスを与えるとホストを制御できてしまいます。そこで、別の [Watchtower](https://github.com/nicholas-fedor/watchtower) コンテナが ipmideck の要求に応じて置き換えを行います。

<Steps>
  <Step title="ipmideck コンテナにラベルを付ける">
    Watchtower による管理を許可するラベルを付けて ipmideck を起動します:

```bash
docker run -d --name ipmideck --network host \
  --label com.centurylinklabs.watchtower.enable=true \
  -v ipmideck-data:/data devluigi06/ipmideck:latest
```
  </Step>
  <Step title="Watchtower を起動する">
    HTTP API を有効にし、ホストからのみアクセスできるようにして Watchtower を起動します:

```bash
docker run -d --name watchtower \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -p 127.0.0.1:8080:8080 \
  -e WATCHTOWER_HTTP_API_UPDATE=true \
  -e WATCHTOWER_HTTP_API_TOKEN=replace-with-a-long-random-token \
  -e WATCHTOWER_LABEL_ENABLE=true \
  nickfedor/watchtower
```
  </Step>
  <Step title="ipmideck を接続する">
    `config.yaml` にすでにある `updates:` セクションに Watchtower のアドレスとトークンを追加し、ipmideck を再起動します:

```yaml config.yaml
updates:
  watchtower_url: http://127.0.0.1:8080
  watchtower_token: replace-with-a-long-random-token
```

    同じ設定は `IPMIDECK_UPDATES_WATCHTOWER_URL` と `IPMIDECK_UPDATES_WATCHTOWER_TOKEN` でも指定できます。両方のコンテナが同じネットワークにある Docker Compose では、アドレスに `http://watchtower:8080` を使用してください。
  </Step>
</Steps>

<Warning>
  Watchtower はソケットを通じて Docker を制御します。長いランダムなトークンを使用し、例のようにポートを `127.0.0.1` にバインドしてください。
</Warning>

<Note>
  Watchtower はコンテナが使用しているタグを取得します。`latest` の場合は最新リリースに移行し、バージョンタグ (例: `2.0.0`) に固定したコンテナはそのバージョンのままです。
</Note>

## インストールに失敗した場合

ダイアログに理由とインストーラーの出力、および手動でインストールするためのコマンドが表示されます。何も削除されません。インストール前に作成したバックアップは `backups/` にあり、復元方法は [バックアップと復元](/ja/backup-restore) で説明しています。
