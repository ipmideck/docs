Gdy zostanie opublikowana nowsza wersja, ipmideck jednorazowo wyświetla powiadomienie, a obok wersji na pasku bocznym pozostaje przycisk aktualizacji, dopóki jej nie zainstalujesz: strzałka w górę lub tarcza w przypadku wydania bezpieczeństwa. Oba otwierają informacje o nowym wydaniu oraz, gdy ipmideck może zainstalować je samodzielnie, przycisk **Pobierz i zainstaluj**.

## Co robi przycisk

Zanim cokolwiek zmieni, ipmideck tworzy kopię zapasową bazy danych, klucza szyfrowania i `config.yaml` w `backups/` w [katalogu danych](/pl/configuration#gdzie-znajduje-się-konfiguracja).

| Metoda instalacji | Wynik |
| --- | --- |
| pip w środowisku wirtualnym, pipx, uv | Instaluje nową wersję i uruchamia ipmideck ponownie. Strona przeładuje się sama, gdy nowa wersja zacznie działać. |
| pip, pipx lub uv w Windows | ipmideck zatrzymuje się, aby można było zainstalować aktualizację, a następnie uruchamiasz go ponownie. Postęp jest zapisywany w `update.log` w katalogu danych. |
| Docker z Watchtower | Watchtower pobiera nowy obraz i zastępuje kontener. Strona przeładuje się sama. |
| Docker bez Watchtower | Okno pokazuje polecenie do uruchomienia na hoście Dockera. |
| Checkout git, systemowy Python, instalacja edytowalna | Okno wyjaśnia przyczynę i pokazuje polecenie do uruchomienia; Python zarządzany przez system aktualizuje się tak, jak został zainstalowany. |

## Wymagania

- Logowanie musi być włączone: przycisk zastępuje działający program.
- Przycisk nie jest dostępny w trybie demo.
- Aby uruchomić się ponownie samodzielnie, ipmideck musi być uruchomiony poleceniem `ipmideck`. Jeśli uruchomiono go inaczej, instaluje aktualizację i prosi o ponowne uruchomienie; w Windows zamiast tego pokazuje polecenie.

## Docker z Watchtower

Kontener nie może zastąpić własnego obrazu, a dostęp ipmideck do gniazda Dockera dałby mu kontrolę nad hostem. Osobny kontener [Watchtower](https://github.com/nicholas-fedor/watchtower) wykonuje wymianę, gdy ipmideck o to poprosi.

<Steps>
  <Step title="Oznacz kontener ipmideck">
    Uruchom ipmideck z etykietą, która pozwala Watchtower nim zarządzać:

```bash
docker run -d --name ipmideck --network host \
  --label com.centurylinklabs.watchtower.enable=true \
  -v ipmideck-data:/data devluigi06/ipmideck:latest
```
  </Step>
  <Step title="Uruchom Watchtower">
    Uruchom Watchtower z włączonym API HTTP, dostępnym tylko z hosta:

```bash
docker run -d --name watchtower \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -p 127.0.0.1:8080:8080 \
  -e WATCHTOWER_HTTP_API_UPDATE=true \
  -e WATCHTOWER_HTTP_API_TOKEN=replace-with-a-long-random-token \
  -e WATCHTOWER_LABEL_ENABLE=true \
  nickfedor/watchtower
```
  </Step>
  <Step title="Połącz ipmideck">
    Dodaj adres Watchtower i token w istniejącej sekcji `updates:` pliku `config.yaml`, a następnie uruchom ipmideck ponownie:

```yaml config.yaml
updates:
  watchtower_url: http://127.0.0.1:8080
  watchtower_token: replace-with-a-long-random-token
```

    Te same ustawienia są dostępne jako `IPMIDECK_UPDATES_WATCHTOWER_URL` i `IPMIDECK_UPDATES_WATCHTOWER_TOKEN`. W Docker Compose, gdzie oba kontenery współdzielą sieć, użyj adresu `http://watchtower:8080`.
  </Step>
</Steps>

<Warning>
  Watchtower steruje Dockerem przez jego gniazdo. Użyj długiego, losowego tokenu i pozostaw port powiązany z `127.0.0.1`, jak w przykładzie.
</Warning>

<Note>
  Watchtower pobiera tag, którego kontener już używa. Z `latest` przechodzi do najnowszego wydania; kontener przypięty do tagu wersji (na przykład `2.0.0`) pozostaje przy nim.
</Note>

## Jeśli instalacja się nie powiedzie

Okno pokazuje przyczynę i wynik instalatora oraz polecenie do ręcznej instalacji aktualizacji. Nic nie jest usuwane: kopia zapasowa wykonana przed instalacją znajduje się w `backups/`, a [Kopia zapasowa i przywracanie](/pl/backup-restore) wyjaśnia, jak ją przywrócić.
