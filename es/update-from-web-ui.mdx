Cuando se publica una versión más reciente, ipmideck muestra una notificación una sola vez, y junto a la versión en la barra lateral permanece un botón de actualización hasta que la instalas: una flecha hacia arriba, o un escudo si es una versión de seguridad. Ambos abren las notas de la nueva versión y, cuando ipmideck puede instalarla por sí mismo, el botón **Descargar e instalar**.

## Qué hace el botón

Antes de cambiar nada, ipmideck hace una copia de seguridad de la base de datos, la clave de cifrado y `config.yaml` en `backups/` dentro del [directorio de datos](/es/configuration#dónde-reside-la-configuración).

| Instalado con | Resultado |
| --- | --- |
| pip en un entorno virtual, pipx, uv | Instala la nueva versión y reinicia ipmideck. La página se recarga sola cuando la nueva versión está en marcha. |
| pip, pipx o uv en Windows | ipmideck se detiene para que se instale la actualización y después vuelves a iniciarlo. El progreso se registra en `update.log` en el directorio de datos. |
| Docker con Watchtower | Watchtower descarga la nueva imagen y sustituye el contenedor. La página se recarga sola. |
| Docker sin Watchtower | El diálogo muestra el comando que debes ejecutar en el host de Docker. |
| Checkout de git, Python del sistema, instalación editable | El diálogo explica el motivo y muestra el comando que debes ejecutar; un Python gestionado por el sistema se actualiza igual que se instaló. |

## Requisitos

- El inicio de sesión debe estar activado: el botón sustituye el programa en ejecución.
- El botón no está disponible en modo demo.
- Para reiniciarse solo, ipmideck debe haberse iniciado con el comando `ipmideck`. Si se inició de otra forma, instala la actualización y te pide que lo reinicies; en Windows muestra el comando en su lugar.

## Docker con Watchtower

Un contenedor no puede sustituir su propia imagen, y dar a ipmideck acceso al socket de Docker le daría el control del host. Un contenedor [Watchtower](https://github.com/nicholas-fedor/watchtower) independiente hace la sustitución cuando ipmideck se lo pide.

<Steps>
  <Step title="Etiqueta el contenedor de ipmideck">
    Inicia ipmideck con la etiqueta que permite a Watchtower gestionarlo:

```bash
docker run -d --name ipmideck --network host \
  --label com.centurylinklabs.watchtower.enable=true \
  -v ipmideck-data:/data devluigi06/ipmideck:latest
```
  </Step>
  <Step title="Inicia Watchtower">
    Inicia Watchtower con su API HTTP activada y accesible solo desde el host:

```bash
docker run -d --name watchtower \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -p 127.0.0.1:8080:8080 \
  -e WATCHTOWER_HTTP_API_UPDATE=true \
  -e WATCHTOWER_HTTP_API_TOKEN=replace-with-a-long-random-token \
  -e WATCHTOWER_LABEL_ENABLE=true \
  nickfedor/watchtower
```
  </Step>
  <Step title="Conecta ipmideck">
    Añade la dirección de Watchtower y su token en la sección `updates:` que ya tiene `config.yaml` y reinicia ipmideck:

```yaml config.yaml
updates:
  watchtower_url: http://127.0.0.1:8080
  watchtower_token: replace-with-a-long-random-token
```

    Los mismos ajustes están disponibles como `IPMIDECK_UPDATES_WATCHTOWER_URL` e `IPMIDECK_UPDATES_WATCHTOWER_TOKEN`. Con Docker Compose, donde ambos contenedores comparten red, usa `http://watchtower:8080` como dirección.
  </Step>
</Steps>

<Warning>
  Watchtower controla Docker a través de su socket. Usa un token largo y aleatorio, y mantén su puerto ligado a `127.0.0.1` como en el ejemplo.
</Warning>

<Note>
  Watchtower descarga la etiqueta que ya usa el contenedor. Con `latest` pasa a la versión más reciente; un contenedor fijado a una etiqueta de versión (por ejemplo `2.0.0`) se queda en ella.
</Note>

## Si la instalación falla

El diálogo muestra el motivo y la salida del instalador, junto con el comando para instalar la actualización manualmente. No se elimina nada: la copia de seguridad hecha antes de la instalación está en `backups/`, y [Copia de seguridad y restauración](/es/backup-restore) explica cómo restaurarla.
